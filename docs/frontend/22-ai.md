# 22 — Interface de IA

Reafirma `docs/ux/06-processos.md §6.2.1` (especificação exaustiva do
painel de resumo) e `docs/api/14-ai.md`. Backend: módulo **AI não
implementado** — só o schema (`ResumoIA`, `FonteIA`) existe (ver
[31-decisions.md §31.1](31-decisions.md)).

## 22.1 Estrutura

```
features/ai/
├── api/{keys,queries,mutations}.ts   → useCaseSummaries(caseId), useSummary(id), useRequestSummary, useRegenerateSummary, useCancelSummary, useSummaryFeedback
├── schemas/stream-event.schema.ts    # Zod runtime — validação de payload SSE, ver 09-openapi.md §9.5
├── components/{ai-summary-card,ai-panel,ai-badge,ai-sources}.tsx
└── index.ts
```

`AISummaryCard`/`AIPanel` é o **único** componente autorizado a usar
`bg-ai-subtle` como fundo de card inteiro e a variante `Button` `ai`
(reafirma [13-design-system.md §13.4](13-design-system.md)) — nenhuma
outra tela usa a cor `--ai` fora de badges/marcadores pontuais.

## 22.2 Streaming — consumindo os eventos SSE do backend

Contrato já fechado em `docs/api/14-ai.md §14.3` (`GET
/ai-summaries/:id/stream`, mesma decisão de auth do §2.9 — cookie
httpOnly, `EventSource`, sem token em query string, mesmo `SseManager`
descrito em [20-notifications-sse.md §20.2](20-notifications-sse.md), uma
segunda instância dedicada a esta stream, não a mesma conexão de
notificações — são recursos diferentes com ciclos de vida diferentes).

```
event: token   → concatena delta ao texto renderizado (cursor piscando, sem
                 transição por palavra — reafirma docs/ux/12-design-system.md §12.8)
event: source  → acrescenta chip de fonte clicável (ordem preservada)
event: done    → marca PRONTO, para a stream, invalida useSummary(id)
event: error   → code AI_PROVIDER_UNAVAILABLE | GENERATION_TIMEOUT | TOKEN_EXPIRED
                 → TOKEN_EXPIRED: refresh + reabre (igual a 20-notifications-sse.md §20.2)
                 → demais: card de erro discreto, "Tentar novamente"
```

Reconectar ao `streamUrl` de uma geração já concluída retorna `done`
imediatamente (reconexão idempotente, já garantido pelo contrato de
backend) — o `AIPanel` trata isso como o caminho normal ao reabrir uma
tela de processo com um resumo já pronto, não como um caso especial.

## 22.3 Estados obrigatórios (reafirma `docs/ux/06-processos.md §6.2.1`)

| Estado | UI |
|---|---|
| Vazio (nenhum resumo ainda) | `EmptyState` "Gerar resumo com IA" |
| Gerando | "Gerando resumo..." + esqueleto de 3 linhas progressivamente substituído pelo streaming |
| Pronto | Texto completo + fontes clicáveis + feedback 👍/👎 + selo obrigatório |
| Erro | Card com borda `danger`, discreto — "Não foi possível gerar o resumo agora" + "Tentar novamente" |
| Desatualizado | Fontes (documentos/eventos) mudaram desde a geração — banner "Este resumo pode estar desatualizado" com atalho para regenerar (ver §22.5) |

**Nunca** um indicador numérico de confiança — confiança é comunicada só
por fontes citadas e linguagem qualificada (decisão de UX já fechada,
não revisitada aqui).

## 22.4 O selo obrigatório e a regra de confiança

Todo `AIPanel`/`AISummaryCard` renderiza, sem exceção e sem opção de
esconder, o rodapé "Gerado por IA — confira antes de usar" (reafirma
`docs/ux/14-ux-writing.md §14.7`). A interface nunca apresenta a saída
como orientação jurídica definitiva — nenhum texto de produto (label,
tooltip, mensagem de erro) usa linguagem que sugira o contrário. Fontes
são navegáveis (clique abre o documento/trecho de origem) **somente**
quando o usuário já tem permissão de leitura sobre a fonte citada — um
resumo pode citar um documento confidencial ao qual o usuário atual não
tem acesso (o resumo em si foi gerado com o contexto completo do
processo); nesse caso o chip de fonte aparece sem link, não com um link
que resultaria em 404 (reafirma
[06-autorizacao.md §6.4](06-autorizacao.md): o frontend não usa um 404
como forma de "ver se dá certo").

## 22.5 Custo, cancelamento, regeneração, invalidação

- **Custo:** nunca mostrado a Advogado/Estagiário; visível só a
  Admin/Owner/Sócio via painel próprio de uso de IA
  (`GET /office/ai-usage`, fora de `features/ai` — mora em
  `features/office/` por ser uma visão administrativa do escritório, não
  do processo).
- **Cancelamento:** `useCancelSummary` fecha a stream client-side
  imediatamente e chama `POST /ai-summaries/:id/cancel`; card volta ao
  estado Vazio.
- **Regeneração:** cria uma nova versão (não sobrescreve) — histórico de
  gerações anteriores acessível via `useCaseSummaries(caseId)`.
- **Invalidação após alteração das fontes:** quando um documento/evento
  citado como fonte de um resumo é alterado ou removido, o resumo não é
  invalidado automaticamente pelo frontend (isso é uma decisão de
  domínio do backend, fora do escopo desta camada) — o frontend só exibe
  o banner de "desatualizado" quando o backend sinalizar isso
  explicitamente no DTO do resumo (campo a confirmar quando o módulo for
  implementado, ver [31-decisions.md §31.9](31-decisions.md)).
- **Cota atingida:** `402`/`403 AI_QUOTA_EXCEEDED` → mensagem exata
  "Este escritório atingiu o limite de resumos de IA do mês. Fale com o
  administrador da conta." (reafirma `docs/ux/14-ux-writing.md §14.7`).
