## 14.1 `POST /v1/legal-cases/:id/ai-summaries`

**Body:** `{ "tipoResumo": "GERAL" }` (`GERAL`\|`EXECUTIVO`\|`CRONOLOGICO`\|
`PONTOS_CHAVE`\|`RISCOS`).
**Resposta 202:**
```json
{ "id": "...", "status": "GERANDO", "streamUrl": "/v1/ai-summaries/.../stream" }
```
**Erros:** `409` (`code: GENERATION_IN_PROGRESS`) se já existe geração
`GERANDO` do mesmo `(processoId, tipoResumo)` — retorna o `id` em andamento
em vez de iniciar outra (reafirma
[../database/06-entidades-ia-notificacoes-auditoria.md §6.1.1](../database/06-entidades-ia-notificacoes-auditoria.md)) ·
`402`/`403` (`code: AI_QUOTA_EXCEEDED`) se a cota mensal do escritório foi
atingida — verificado **antes** de criar a linha `PENDENTE` (reafirma
[../database/12-eventos-fluxos-regras.md §12.3.8](../database/12-eventos-fluxos-regras.md)).
**Idempotência:** `Idempotency-Key` obrigatório.
**Regra:** se já existe resumo `vigente = true` deste tipo com
`hashContexto` idêntico ao estado atual do processo, a API retorna
imediatamente esse resumo com `status: PRONTO` (cache), sem chamar o
provedor de IA.

## 14.2 `GET /v1/ai-summaries/:id`

**Resposta 200:**
```json
{
  "id": "...", "processoId": "...", "tipoResumo": "GERAL", "status": "PRONTO",
  "conteudo": "O processo trata de uma reclamação trabalhista...",
  "modelo": "claude-opus-5", "promptVersion": "resumo-geral-v3",
  "geradoEm": "2026-08-10T10:00:00.000Z", "vigente": true,
  "feedback": null,
  "fontes": [
    { "id":"...", "sourceType":"DOCUMENTO", "sourceId":"...",
      "trechoOuReferencia":"Petição inicial, p.2", "ordem":1 }
  ]
}
```
**Campo `custoEstimadoCentavos`/`tokensEntrada`/`tokensSaida`:** presentes na
resposta apenas quando o solicitante tem `ai:usage:read` — reafirma
[../ux/06-processos.md §6.2.1](../ux/06-processos.md) ("custo não é exibido
ao Advogado/Estagiário"); omitidos (não apenas zerados) do JSON para os
demais papéis.

## 14.3 `GET /v1/ai-summaries/:id/stream` (streaming da geração)

**Mecanismo: SSE**, aberto pelo frontend imediatamente após o `202` de
`POST .../ai-summaries` (reafirma preferência de
[../05-arquitetura-backend.md §5.11](../05-arquitetura-backend.md) e
comportamento de [../ux/06-processos.md §6.2.1](../ux/06-processos.md), "o
texto aparece enquanto é gerado"). Autenticado por **cookie `httpOnly`**
(`EventSource` nativo) — decisão e justificativa completa em
[02-autenticacao.md §2.9](02-autenticacao.md).

**Eventos:**
```
event: token
data: {"delta":"O processo "}

event: token
data: {"delta":"trata de uma "}

event: source
data: {"ordem":1,"sourceType":"DOCUMENTO","sourceId":"...","trechoOuReferencia":"Petição inicial, p.2"}

event: done
data: {"id":"...","status":"PRONTO","tokensEntrada":1450,"tokensSaida":320}

event: error
data: {"code":"AI_PROVIDER_UNAVAILABLE","message":"..."}
```
- `token`: fragmento incremental de texto — o frontend concatena `delta` em
  ordem de chegada.
- `source`: emitido conforme cada fonte é identificada pelo `ContextBuilder`
  (pode chegar antes, durante ou depois do texto — o frontend renderiza a
  lista de fontes de forma incremental, reafirma
  [../ux/06-processos.md §6.2.1](../ux/06-processos.md)).
- `done`: encerra o stream, conexão fecha. Cliente busca o recurso completo
  via `GET /v1/ai-summaries/:id` se precisar do objeto integral (o stream não
  reenvia o texto completo, só os deltas).
- `error`: encerra o stream sem `done`; frontend exibe o estado de erro de
  [../ux/06-processos.md §6.2.1](../ux/06-processos.md) ("Não foi possível
  gerar o resumo agora").
- **Timeout de stream:** 60s sem evento novo → servidor fecha com `error`
  (`code: GENERATION_TIMEOUT`).
- Reconectar a um `streamUrl` de uma geração já concluída retorna
  imediatamente `done` com o resultado final (idempotente a reconexão).

## 14.4 `POST /v1/ai-summaries/:id/regenerate`

**Resposta 202**, mesmo formato de criação — cria nova linha
(`versaoResumo + 1`), marca a anterior `vigente = false`. **Nunca** faz
`UPDATE` sobre conteúdo já gerado (reafirma
[../database/06-entidades-ia-notificacoes-auditoria.md §6.1.2](../database/06-entidades-ia-notificacoes-auditoria.md)).

## 14.5 `POST /v1/ai-summaries/:id/cancel`

**Resposta 204.** Encerra a chamada ao provedor em curso (best-effort — se o
provedor já retornou, o cancelamento é ignorado silenciosamente) e marca
`status = FALHA` com `erro: "Cancelado pelo usuário"`.

## 14.6 `POST /v1/ai-summaries/:id/feedback`

**Body:** `{ "feedback": "NEGATIVO", "comentarioFeedback": "Faltou mencionar o prazo recursal" }`
— `comentarioFeedback` sempre opcional (reafirma
[../ux/14-ux-writing.md §14.7](../ux/14-ux-writing.md), nunca obrigatório).
**Resposta 204.**

## 14.7 `GET /v1/office/ai-usage`

**Resposta 200:**
```json
{ "mesReferencia": "2026-08", "resumosGerados": 42, "cotaMensal": 200,
  "custoEstimadoCentavosTotal": 1850, "porTipo": {"GERAL": 30, "EXECUTIVO": 12} }
```
Reafirma [05-offices.md §5.4](05-offices.md) — mesmo dado exibido em dois
endpoints por conveniência de contexto de tela (perfil de uso geral do
escritório vs. detalhe de um resumo específico).
